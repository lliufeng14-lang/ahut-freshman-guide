排行榜云端配置指南

让「2048对战」的合成榜变成真正的全站实时排行榜：所有玩家的最高分自动上榜、实时排名，人人可见。

🚦 先看懂现状

原版 2048 的排行榜按钮存在，但它的数据接口指向网站自身（location.origin/api/...），在 GitHub Pages 这种纯静态托管下必然失败，只能看到自己浏览器里的本地记录——别人根本看不见你。

本次改造后（双后端兼容）：

  • 未配置：自动进入「本地模式」，排行榜弹窗可用，记录仅本机可见（不影响玩）。
  • 配置 Supabase（推荐，本指南）：合成榜实时显示每个玩家的最高单局分数 + 排名，10 秒自动刷新，人人可见。
  • 配置 LeanCloud（备选）：同样可用，见文末附录。
✅ 两种后端自动识别，配置填哪个就用哪个，无需改游戏代码。

🧭 为什么用 Supabase

优势

  • 谷歌 / GitHub 账号一键注册，不用手机号
  • 免费版：50 万次请求/月、500MB 数据库，校园规模绰绰有余
  • 新加坡节点，国内访问速度可接受

  • 约 10 分钟操作时间
  • 全程在浏览器里点，无需安装任何软件

🛠 开通步骤（约 10 分钟）

1
用谷歌账号登录 Supabase
浏览器打开 supabase.com → 点右上角 「Start your project」 → 选 「Continue with Google」（用你的谷歌账号）。首次登录可能要求填一个 Organization 名称，随便填（如 ahut）。
2
创建项目
点 「New project」，填写：
  • Organization：选默认那个
  • Name：ahut-2048（随意）
  • Database Password：设一个密码（必须设，记不住就点 Generate 生成并抄下来）
  • Region：选 Singapore（亚太节点，国内访问最快）
点 「Create new project」，等 1~2 分钟自动创建完成。
3
执行建表 SQL（一键搞定表 + 权限）
左侧菜单点 「SQL Editor」 → 「New query」，把下面整段代码粘贴进去，点右下角 「Run」（绿色按钮）。显示 Success 即可：
-- 排行榜数据表 + 匿名访问权限（一键执行） create table if not exists lb_scores ( id bigint generated always as identity primary key, mode text not null, name text not null, score bigint not null default 0, max_tile bigint not null default 0, total_score bigint not null default 0, games bigint not null default 0, created_at timestamptz not null default now(), unique (mode, name) ); alter table lb_scores enable row level security; create policy "公开读取" on lb_scores for select using (true); create policy "公开写入" on lb_scores for insert with check (true); create policy "公开更新" on lb_scores for update using (true); create policy "公开删除" on lb_scores for delete using (true);
⚠️ 这步必须执行：Supabase 新项目默认拒绝匿名访问，不建策略的话玩家上不了榜。上面这段代码把表建好并把权限全开（适合校园排行榜这种公开数据）。
4
复制两个值（发给 AI 助手）
左侧 「Project Settings」（最底部齿轮图标）→ 点 「API」，页面上找到并复制：
  • Project URL：形如 https://abcdefghijk.supabase.co
  • anon public key：一长串 eyJ... 开头的字符串（⚠️ 是 anon 那个，不是 service_role，service_role 绝不能给前端）
把这两个值发给 AI 助手，他会帮你填进 game2048.html。
5
部署并验证
AI 填好配置后，把 game2048.html 重新部署到 GitHub Pages。打开游戏 → 玩一局 → 点「🏆 排行榜」→ 切到「合成榜」，看到自己上榜、按钮出现绿色「● 实时」即成功。手机玩一局，电脑端也能看到。

📊 榜单规则

榜单排序依据记录方式
合成榜（主榜）每位玩家的最高单局分数，降序排名同一玩家同一模式只保留一条（数据库唯一约束 mode+name），取最高分；同时记录最大合成数与累计总分
PK 积分榜在线 PK 积分累加，降序排名同一玩家只保留一条，积分累加

数据表 lb_scores 的字段：mode（pk/merge）、name（玩家昵称）、score（合成榜=最高分 / PK榜=累计积分）、max_tile（最大合成数）、total_score（累计总分）、games（对局次数）、id（自动生成）。

其他说明

  • 昵称：第一次玩 PK 或打开排行榜时会提示设置昵称（最长 12 字），保存在浏览器里，可随时修改。
  • 刷新频率：排行榜打开时每 10 秒自动刷新一次。
  • 清空榜单：排行榜弹窗右下角「清空」按钮，云端模式下会同时清空云端数据（慎用）。

❓ 常见问题

  • 排行榜按钮没有「● 实时」绿点？ → 说明没进云端模式：检查两个值是否填对、是否已重新部署、项目是否创建完成。
  • 玩了一局但合成榜没我？ → 确认分数大于 0（空局不上报）；再确认第 3 步 SQL 执行成功（Success）。
  • 报错 401 / 403？ → 建表 SQL 没执行成功，或 anon key 复制错了。
  • 本地双击打开测试时不上榜？ → 正常，浏览器限制 file:// 直连云端。部署到线上（或本地起 HTTP 服务）再测。
  • anon key 写在网页里安全吗？ → 安全。anon key 就是给前端公开用的；千万别把 service_role key 写进前端（那个能绕过所有权限）。
  • 免费额度够吗？ → 50 万次/月请求，按每 10 秒刷新一次算，几千人同时用都够。

📎 附录：备选方案 LeanCloud（国内版）

如果想换用 LeanCloud（国内节点，但需手机号注册，近期注册可能不稳定），代码也已兼容：

<!-- 与 Supabase 配置二选一，填在 game2048.html 的 <head> 后 --> <script> window.LB_CONFIG = { leancloud: { appId: "你的AppID", appKey: "你的AppKey", server: "https://你的API服务器地址" } }; </script>

LeanCloud 版需手动建 Class「LBScore」并把权限设为「无限制」。两个后端同时填了配置时，Supabase 优先。
